# Database Migrations and Admin Seeding

EF migrations own schema creation and the default company row. Runtime seeding only creates or updates the break-glass admin account from environment variables.

Primary keys are generated by the application with `.NET 10` `Guid.CreateVersion7()`. Migrations do not require PostgreSQL `pgcrypto`, `CREATE EXTENSION`, or `gen_random_uuid()`.

## Required environment variables

Set these in the shell, deployment environment, or Azure App Service configuration before running migrate-and-seed:

```sh
export ConnectionStrings__NeoBankingDb="<postgres connection string>"
export SeedAdmin__Email="admin@example.com"
export SeedAdmin__Password="<admin password>"
```

Committed appsettings files include only placeholder `ConnectionStrings:NeoBankingDb` values. Use environment variables, Azure App Service configuration, or a local untracked settings file for real connection strings.

Optional:

```sh
export SeedAdmin__DisplayName="Admin"
```

Do not commit these values. `SeedAdmin__Password` is hashed with ASP.NET Core Identity before storage; the plaintext password is not stored by the application.

## Apply migrations and seed admin

From the repository root:

```sh
dotnet run \
  --project backend/src/NeoBanking.Api/NeoBanking.Api.csproj \
  -- --migrate-and-seed
```

The command runs `Database.MigrateAsync()`, ensuring the `neobanking` schema, tables, indexes, and migration-seeded default company exist. It then creates or updates the local admin identity under the default company using `SeedAdmin__Email` and `SeedAdmin__Password`.

The command prints the admin email used. It never prints the password.

## Generate future migrations

Use Infrastructure as the design-time startup project because `NeoBankingDbContextFactory` and the EF Design package live there:

```sh
dotnet ef migrations add <MigrationName> \
  --project backend/src/NeoBanking.Infrastructure/NeoBanking.Infrastructure.csproj \
  --startup-project backend/src/NeoBanking.Infrastructure/NeoBanking.Infrastructure.csproj \
  --context NeoBankingDbContext \
  --output-dir Persistence/Migrations
```

Keep company seed data in migrations. Do not add admin credentials to migrations or appsettings files. New entity IDs should come from the domain entity defaults, not PostgreSQL UUID defaults.
