# NeoBanking Persistence Notes

## PostgreSQL conventions

- Primary keys are `Guid` values generated by the application with `.NET 10` `Guid.CreateVersion7()`. PostgreSQL deployments do not need `pgcrypto` or `gen_random_uuid()` for ID creation.
- Company-scoped tables carry a required `CompanyInstallationId` and company indexes. This is a single-company installation model, not multi-tenant SaaS isolation.
- Workflow and lifecycle values are modeled as bounded strings rather than PostgreSQL enum types. This keeps migrations simpler while product states are still changing.
- JSON payloads are string properties mapped to `jsonb` columns. This avoids depending on EF Core owned JSON mapping while still letting PostgreSQL validate and index JSON later.
- Money-like values use minor units (`long`) plus a three-character currency code to avoid decimal rounding ambiguity.
- Most delete paths are configured as `Restrict` to prevent accidental company, user, or compliance data loss.

## Main aggregates

- `CompanyInstallation` stores the one deployed customer/company profile, branding metadata, and installation settings.
- `ApplicationUser`, `UserIdentity`, and `RefreshSession` cover user records, external identity subjects, and refresh-token session tracking.
- `AdminProfile` separates privileged operator state from ordinary user data.
- `ProviderMapping` stores durable links between internal entities and upstream banking, card, identity, or compliance providers.
- `OnboardingApplication`, `KycVerification`, and `KybVerification` hold onboarding workflow state and provider check payloads.
- `BankingSnapshot` stores point-in-time upstream banking data such as account or balance snapshots.
- `PaymentCard` stores card lifecycle metadata only. PAN, CVV, and raw sensitive card data are intentionally absent.
- `WebhookEndpoint` and `WebhookDelivery` support inbound/outbound delivery tracking, retries, and provider event de-duplication.
- `IdempotencyRecord` protects command endpoints from duplicate processing.
- `AuditLogEntry` records security, compliance, and operational events.

## Indexing notes

- Unique keys protect company slugs, company-local user emails, provider subjects, provider mappings, provider card IDs, webhook provider event IDs, and idempotency keys.
- Status and retry indexes are included for worker polling.
- Audit indexes favor chronological company queries, actor activity, entity history, and trace correlation.

## Future migration notes

- Consider GIN indexes on heavily queried `jsonb` columns after query patterns are known.
- Consider table partitioning for `audit_log_entries`, `webhook_deliveries`, and `banking_snapshots` once retention and volume targets are clear.
- If a global snake_case naming convention is added later via Npgsql conventions, keep explicit table names and verify generated column names before the first production migration.
